## 三张"该往哪儿写"的判据（避免同类内容长两处）

1. **"今天发现了一个缺陷"** → roadmap 的 #1xx（含判据与属人/属机器标注），**不要**写进 `docs/evolution/` 任何文件。
2. **"我写下了一个待验的预期"** → `EXPERIMENT_LOG.md`（它必须早于读数存在；事后补的不算）。
3. **"我要引用一个数"** → 先问它是**水位**（→ `BASELINE.md`，带 tick）还是**速率/斜率**（→ `CPU_BENCHMARKS.md`，带窗口与仪器名）；两者不可互换，跨 boot 段的累计量必须差分。

## 本目录的更新纪律

- 只有"文件搬家/新增/改名"才动这张表；内容结论一律回到各自真身去改。
- 编号唯一性：#1xx 与 `R###` 各自递增且**跨会话共享**（本工作区多路会话并行写），动笔前先 grep 现号取满，别撞号（本表 R329 时 #115/#116/#117 已被并行会话占用 ⇒ 新条只能 #118 起）。
- 任何一份文件都不得声称"§7 已完成"，除非本表的 ⚠️ 两项被要么补件、要么在 L0 里写明映射（后者是**属人决定**，不由我单方改 L0）。
