# 25 · 架构取舍台账（ARCHITECTURAL_TRADEOFFS）

> 研究文档 · 结论等级：**设计裁决（张力分析层）**。与
> [ARCHITECTURE_DECISIONS.md](ARCHITECTURE_DECISIONS.md) 的分工：ADR 是**裁决
> 记录**（Context/Options/Decision），本文是**张力和代价的分析**——每条取舍回答
> 「张力是什么、证据是什么、选了什么、付什么价、还有多少回旋余地」。26 号 §3
> 的唯一写者所有权模型在此展开。bot 证据见
> [02_EXISTING_BOT_ANALYSIS.md](02_EXISTING_BOT_ANALYSIS.md)。核查日：2026-08-22。

## 1. Problem

没有显式台账的架构取舍会经历三种死亡：(1) 半年后没人记得为什么选 A，在新需求
下静默改成 B，旧代价回来了；(2) 只记录了选择，没记录代价——代价被当成 bug 修
（越修越歪）；(3) 没记录回旋余地——不知道哪些门已关死、哪些还能重开。本套件
12 条 ADR 是裁决的骨架，本文给每条裁决（及其下隐含子取舍）补上**张力-证据-
选择-代价-回旋余地**五元组，使未来修订可以基于完整信息而非重新争吵。

## 2. Research Questions

- 本套件全部裁决背后有哪些结构性张力（A vs B）？
- 每条张力的社区/bot 证据与机制证据是什么？
- 每条选择的真实代价（不是收益）是什么？代价何时会变成痛点？
- 哪些取舍是单向门（不可逆），哪些是双向门（可回退）？
- 有没有「两头下注」的正确姿势（混态/适配层）？

## 3. Existing Solutions（取舍方法论）

- **单向门/双向门**（one-way/two-way door）：不可逆决策必须慢与重（ADR 流程），
  可逆决策应快与轻（tuning 层）。本文对每条取舍标注门性。
- **可选性**（optionality）：保留未来选择权的代价是当下的复杂度；正确姿势是
  「为可预期的变化买期权，不为想象的变化买保险」（如版本化模板买的是迁移期权，
  不是算法生成保险）。
- **显式代价记账**：每个架构选择同时登记「放弃了什么」——与 ADR 的
  Trade-offs 字段对应，本文更细。
- **混态裁决**：多数真张力不是二选一而是边界划定（请求制 vs 配额制 → 按资源
  频率分界，04 号 §5）。识别「张力其实是一条谱」本身是方法论输出。

## 4. Screeps Community Practice（六大 bot 的取舍账单）

| Bot | 重大取舍 | 换来 | 付出的价 | 门性 |
| --- | --- | --- | --- | --- |
| Overmind | 7 层 OO 抽象 | 新行为局部性（挂 Directive 即可） | 理解/实例化/贡献门槛三税；exploitable | 单向（代码遗产） |
| TooAngel | 平铺+极简决策 | 十年单人可维护；全局可达性 | 多房协调弱；猴子补丁；路径债 | 单向 |
| TI | 请求经纪经济 | 缺口全显式化；GCL 18.2 亿存活 | 自认意大利面；撮合成本 | 双向（请求池可缩放） |
| Quorum | OS 进程内核 | 调度语义完备 | 维护税→2021 项目死 | 单向（沉没） |
| KasamiBot | 固定蝴蝶模板+按房队列 | 防御可预期；文档详尽 | 适配弱；多房协调弱；不可考古 | 单向 |
| hivemind | 刻意限武 | 生态位（社区接受+活跃维护） | 无进攻数据；天花板低 | 双向（可加攻击模块） |

横向结论：**存活者不是选对了边，而是付出的价与其维护能力匹配**（TooAngel 单人
纪律 ↔ 平铺；hivemind 社区生态位 ↔ 限武）。

## 5. Existing Bot Analysis（本套件裁决性取舍的证据面）

- T-01（内核形态）：Quorum（OS）vs TI/KasamiBot/TooAngel/bonzAI（平铺）战绩
  对比 + hivemind（轻量进程）折中存活——语义与载体分离的证据（19 号 §5）。
- T-03（战略层形态）：TooAngel 三指标十年 vs Overmind 决策树+请求队列——无一家
  效用竞拍的存活样本（06 号）。
- T-05（spawn 形态）：6 家孵化队列收敛，但按房（KasamiBot）与集中（hivemind
  spawn-manager、Overmind hatchery）并存——集中侧信息全、多房代孵可行。
- T-06（请求 vs 配额）：TI requests 现役最强证据；TooAngel 顺路投递是近似解
  极致（ADR-006）。
- T-07（布局）：固定阵营（KasamiBot/Overmind bunker）长期存活；算法阵营
  （bonzAI/Quorum）全部停更或实验化（13 号）。
- T-14（大而全 vs 能用就好）：KasamiBot（大而全攻击性，死）vs hivemind（能用
  就好限武，活）——与「维护能力匹配」结论互证。

## 6. Advantages（台账化的收益）

1. 修订有据：重开某条取舍时，先看代价与门性，而非重新考古。
2. 「代价即 bug 报告」的判别力：收到「XX 好慢/好繁琐」反馈时，先对照台账确认
   是否为已登记代价（预期内）还是新缺陷。
3. 期权意识：明确哪些决策留了适配层（可回退），哪些必须靠版本迁移消化。
4. 与红队联动：30 号红队攻击优先打「已登记代价」的兑现路径。

## 7. Disadvantages（诚实代价）

- 台账维护本身有成本：ADR 修订时本文须同步（两份真相源风险，靠互引纪律压低）。
- 张力描述永远滞后于新张力：新系统引入的新取舍需主动登记。
- 「回旋余地」是研究判断，未经重构实证（标注为 SPECULATION 级）。

## 8. Failure Modes（取舍治理的失败形态）

| 失败模式 | 症状 | 防线 |
| --- | --- | --- |
| 静默翻案 | 无 ADR 修订就把选择 B 的代码合入 | 蓝图冻结纪律：结构修订走 ADR（AGENTS 约束） |
| 代价失忆 | 已登记代价被当 bug 反复「修复」，两头下注漂移 | 代价字段进台账；评审对照 |
| 两头下注 | 同一资源既有请求制又有配额制双通道 | 混态必须有分界判据（资源频率），禁止并存 |
| 单向门当双向门用 | 轻率改布局模板/posture 语义导致不可回退 | 门性标注：模板改动必须版本迁移（ADR-007） |
| 台账腐烂 | 文档与代码漂移 | 本文与 ADR 互引 + 红队每轮抽查 |

## 9. CPU Implications

- 各取舍的 CPU 侧量级已分散入对应文档：T-01 调度税（19 号 §9）、T-04/T-13
  意图仲裁成本上限（20 号 §12.3）、T-10 Memory 税（18 号 §9）、T-06 撮合成本
  （12 号）。本文不重复，仅强调取舍原则：**为确定性付的 CPU 永远优先于为最优
  性付的 CPU**——前者买可测试与可预算，后者买不可复现的边际收益。
- 唯一新增量级：台账本身零 CPU（研究文档不进 tick 路径）。

## 10. Recommended Design（取舍台账本体）

> 每条：张力 → 证据 → 选择 → 代价 → 回旋余地（门性）。裁决全文见对应 ADR。

### T-01 轻量内核 vs OS 内核 / 平铺裸循环
- **张力**：调度语义完备性 vs 结构税与维护税。
- **证据**：Quorum（OS）GCL 45 亿但 2021 停更；平铺阵营战绩最好；hivemind 轻量
  进程活跃（19 号 §5）。抢占在单线程 tick 不存在（机制推导）。
- **选择**：固定顺序系统管线 + safeRun + 四档看门狗 + 注册表组合根（ADR-002）。
- **代价**：放弃动态重排；注册顺序即隐性依赖（bootstrap 作者必须懂顺序）；
  分频靠系统自降频而非调度器。
- **回旋余地**：**双向门**——若 GCL 10+ 分片需求成立，注册表可按房分片而不动
  系统 internals（19 号 §12.3 留口）。

### T-02 帝国-房间两级 vs 房间全自治 / 全集中
- **张力**：扩展性/故障隔离 vs 仲裁权威。
- **证据**：7/7 bot 收敛两级分离（02 号 §6 C1）；A 死锁、B 带宽爆炸（ADR-001）。
- **选择**：帝国管战略/跨房/军事，房间管本地经济闭环；下发预算与承诺非动作。
- **代价**：边界永远需要维护（什么上移是永恒争论）；房间报告质量=帝国决策质量。
- **回旋余地**：双向门——分组键可从「帝国-房间」演化为「主城-卫星」（Overmind
  Colony 式），04 号 §12.2 留口。

### T-03 posture 状态机 vs 每 tick 效用竞拍
- **张力**：可解释/可测试 vs 表达力。
- **证据**：无竞拍存活样本；TooAngel 三指标+滞回十年（ADR-003；06 号）。
- **选择**：战略层=确定性纯函数（posture×budget），Goal 竞争=允许集∩门控∩优先级序。
- **代价**：姿态切换点需精心滞回；新增战略行为=扩语义而非加竞拍项；模糊决策
  （外交）上限由规则设计决定。
- **回旋余地**：单向门（部分）——posture 集合扩展容易，但引入竞拍等于推翻
  ADR-003，须全套重审。

### T-04 声明式 RolePolicy+统一引擎 vs creep 自治散装 FSM
- **张力**：行为一致性/可批量测试 vs 钩子模型表达力。
- **证据**：「角色薄、引擎厚」收敛（TI/hivemind/TooAngel）；全房扫描器是社区
  记录的反模式（ADR-004）。
- **选择**：gate/acquire/work/hold/onFlee/park/combat 七钩子 + role-runner。
- **代价**：非常规行为表达力弱（须引擎扩钩子）；引擎成为关键路径。
- **回旋余地**：双向门——钩子集合可增；单角色的逃生舱是 combat/park 钩子扩展。

### T-05 集中 Spawn Manager（唯一写者）vs 按房孵化队列
- **张力**：全局信息与幂等 vs 房间自治与简单。
- **证据**：6 家孵化与角色解耦收敛；集中侧（hatchery/spawn-manager）支持多房
  代孵与全局能量核算；KasamiBot 按房队列止步单房视角（02 号）。
- **选择**：唯一写者+幂等 key 合并+优先级车道+紧急车道（ADR-005）。
- **代价**：管理器是关键路径（需熔断降级）；单点 bug 影响全帝国人口。
- **回旋余地**：双向门——管理器内部可按房分队列（实现细节），对外仍唯一写者。

### T-06 请求牵引物流 vs 配额推派（vs 全局最优求解）
- **张力**：需求可见性 vs 实现简单；近似 vs 最优。
- **证据**：Overmind 论证 hauling NP-hard；TI requests 现役；TooAngel 顺路投递
  极致近似（ADR-006）。
- **选择**：混态——高频流动资源请求池+租约；低频战略资源配额（04 号 §5）。
- **代价**：两套语义并存（分界判据必须明确）；次优路径浪费部分运力。
- **回旋余地**：双向门——分界判据可按 P6 运行数据移动。

### T-07 版本化布局模板 vs 逐房算法生成
- **张力**：可审计/可迁移/防御可预期 vs 地形适配上限。
- **证据**：模板阵营长期存活、算法阵营停更/实验化（13 号 §4）。
- **选择**：版本化 stamp 模板+低频局部适配+交通热度铺路（ADR-007）。
- **代价**：极端地形房间适配弱；模板错误会被批量复制（靠版本迁移消化）。
- **回旋余地**：**单向门**——核心结构落地后不可自动拆改（冲突只标 blocked）；
  唯一回退是模板版本迁移。

### T-08 投资式扩张门控 vs GCL 一到就 claim
- **张力**：增长速度 vs 本土安全。
- **证据**：过度扩张是社区高频死因；TooAngel 三指标门控十年（ADR-008）。
- **选择**：评分+资源门控（CPU 平滑/净流/运力/可撤离）+殖民自举车道。
- **代价**：错过窗口期（保守税）；门控指标标定需要 soak 数据。
- **回旋余地**：双向门——门控阈值是 tuning 参数；车道机制不变。

### T-09 War 授权+止损链 vs 军事系统自主反应
- **张力**：反击速度 vs 战争经济失控风险。
- **证据**：帝国死于战争经济多于战斗（ADR-009）；TooAngel 三级升级门槛同族；
  hivemind 干脆限武。
- **选择**：war 姿态唯一授权；止损链不可绕过；黑名单冷却。
- **代价**：授权链长→反击延迟（用预警性 fortify 补偿）；确定性行为可被摸透
  （黑名单到期降档重试缓解）。
- **回旋余地**：双向门——授权条件与止损阈值可调；授权链结构本身单向（拆链=新 ADR）。

### T-10 三级存储瘦 Memory vs 单层便利 Memory
- **张力**：每 tick 税 vs 写代码便利。
- **证据**：Memory 序列化计 CPU（官方）；TooAngel 路径债与 MemHack 演进史（18 号）。
- **选择**：瘦 Memory/heap 可丢/segment 冷数据+版本化迁移（ADR-010）。
- **代价**：三级心智负担；segment 异步性把冷数据挡在生存链路外；迁移纪律强制。
- **回旋余地**：双向门（部分）——字段可在级间迁移（路径从 Memory 挪 heap 的
  TooAngel 反例证明代价方向）；schema 版本化使回退可编排。

### T-11 确定性决策+体外 LLM vs 线上智能/在线学习
- **张力**：先进性叙事 vs 可测试/可预算/物理可行。
- **证据**：零线上先例；无出站网络（物理否决）；Overmind-RL 体外先例（ADR-011/23 号）。
- **选择**：LLM=体外研究员+低频有界参数顾问+灾难接管辅助；tick 路径恒零。
- **代价**：模糊决策质量上限锁死在规则设计；体外顾问延迟以统计窗口计。
- **回旋余地**：单向门（物理）+双向门（顾问白名单可扩）。

### T-12 验收制门槛（A0–A5）vs 功能清单 MVP
- **张力**：交付节奏 vs 自治可验证性。
- **证据**：「能运行」无法验证自治；bonzAI 诚实分级先例（ADR-012）。
- **选择**：每门槛场景矩阵+指标阈值+退出条件；MVP=A1+A2。
- **代价**：前期进度可见性低（门槛未过=无「半自治」可炫耀）；门槛本身需维护。
- **回旋余地**：双向门——阈值随 soak 数据调整；门槛结构稳定。

### T-13 集中交通仲裁（tick 末签发）vs 各自移动
- **张力**：全局通行效率/去重 vs 即时性。
- **证据**：intent 0.2 CPU 失败也收费；100 creep 移动 ≈20 CPU（20 号 §3）；
  Overmind init/run 相位分离同构（意图登记后统一执行）。
- **选择**：角色登记移动意图，tick 末按房仲裁统一签发；寻路三档限频。
- **代价**：仲裁器是新的规模热点（200+ creep 同房待验证，20 号 §12.3）；移动
  决策延迟一个相位。
- **回旋余地**：双向门——仲裁可降级为「仅冲突格仲裁」的弱形态。

### T-14 「大而全」vs「能用就好」的生存主义哲学
- **张力**：能力天花板 vs 维护与生态承受力。
- **证据**：KasamiBot 大而全攻击性强但单人终止；hivemind 限武却最活跃；TI 只做
  防御强、战斗自评 dysfunctional 仍 GCL 18.2 亿——**生存闭环优先于发展速度**
  （项目信条）的生态级验证。
- **选择**：能力按生存价值排序交付（防御先于军事 P8<P9；远矿先于扩张 P5<P7）；
  攻击能力存在但永远从属于经济裁决（ADR-009）。
- **代价**：上限低于「大而全」形态；错过纯军事窗口期。
- **回旋余地**：双向门——Phase 10+ 高级经济可逐步扩展，不推翻既有结构。

## 11. Alternatives Rejected（元取舍：为什么没有「全都要」）

| 元方案 | 否决理由 |
| --- | --- |
| 两头下注（每条张力各做一套，运行时选） | 双实现双维护面；运行时切换=新的状态不一致源；Screeps 尺度付不起（Quorum 教训的变体） |
| 全部押注可逆性（只做双向门决策） | 布局落地、spawn 唯一写者、posture 语义天然单向；假装可逆反而放弃版本化迁移的严肃性 |
| 推迟全部取舍（先写代码再抽象） | 「缺环时新增功能会加速失败」（24 号 §1）；取舍延迟=债务前置 |
| 外包取舍给算法（运行时自动选择架构形态） | 自指系统：架构选择的决策质量不可能超过其决策器的质量；不可测试 |
