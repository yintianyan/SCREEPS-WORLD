# 27 · 实施路线图（验收制）

> 研究文档 · 结论等级：**决策已定**。路线由研究推导（证据见各主题文档），不是功能
> 清单：每个 Phase 有前置依赖、交付物、可观察验收门槛与回退路径。门槛分级依据
> [ARCHITECTURE_DECISIONS.md](ARCHITECTURE_DECISIONS.md) ADR-012。

## 1. Problem

「先做 Economy 再做 Military」式的路线无法回答：做到什么程度算完成？错误顺序
会怎样？本路线图把实施变成一组**可验收的自治门槛**（A0–A5），并论证依赖关系。

## 2. 总原则（来自研究结论）

1. **先闭环再扩展**：任何时刻系统必须是一个完整的感知→决策→执行→反馈闭环，
   缺环时新增功能会加速失败（见 [24_FAILURE_MODES.md](24_FAILURE_MODES.md)）。
2. **生存优先级不可倒置**：CPU 死亡循环是帝国头号死因（社区多起 overnight
   collapse 案例），降级链（保 spawn > 保经济 > 保发展）必须最先存在。
3. **每个 Phase 交付「能力 + 验收 + 回退」三件套**，不是交付代码行数。
4. 冷启动 bootstrap 与运营同等重要：自治 AI 必须把「从零建房」当一等公民路径
   （社区重开失败的主因）。

## 3. 验收门槛总表（A0–A5）

| 门槛 | 名称 | 必须证明 | 对应 Phase |
| --- | --- | --- | --- |
| A0 | 可运行 | 空/旧 Memory 可恢复；入口错误被隔离；可构建可观测 | P1 |
| A1 | 生存闭环 | 空 Memory 自举：采能→spawn→升级→基础建造无人工指令 | P2 |
| A2 | 产能闭环 | 稳定能量净流；storage/link 物流按供需运行；CPU/Memory 有预算 | P3–P4 |
| A3 | 多房自治 | 房间注册、远矿、跨房资源平衡、扩张有优先级与取消条件 | P5–P7 |
| A4 | 威胁下运营 | 情报置信度、警报/围城/恢复状态机、战时经济、safemode 预算 | P8–P9 |
| A5 | 长期不退化 | soak 无 Memory 单调膨胀、无任务饥饿、无 bucket 枯竭、重置可恢复 | P10+ |

## 4. Phase 序列

### Phase 0 — Research（本次执行）
研究问题、资料来源、事实核查、bot 考古、架构决策与红队。产出 = 本套件。
**完成判据**：全部 34 份文档 + ADR + 来源台账 + 红队修订闭环。

### Phase 1 — 运行时基座（→A0）
- **交付**：轻量内核（固定顺序系统管线 + safeRun 错误隔离 + 四档 bucket 看门狗
  按 `Game.cpu.limit` 比例化 + 滞回）；Memory schema 版本化与幂等迁移骨架；
  唯一组合根（注册式插件）；瘦 Memory / heap 缓存 / segment 三级存储骨架。
- **依赖**：无（一切的地基）。
- **验收**：空 Memory、损坏 Memory、旧版本 Memory 三场景恢复；单系统抛错不中断
  tick；bucket 人工压低触发降级且恢复走滞回。
- **回退**：内核骨架独立于业务，无回退依赖。

### Phase 2 — 单房生存闭环（→A1，MVP 第一半）
- **交付**：感知层（房间快照/共享索引）；静态矿工+container 模式；hauler 请求池
  （最小版）；集中 spawn manager（人口普查→需求→比例化 body，紧急车道 ≥200 能量
  [WORK,CARRY,MOVE]）；upgrader；基础建造队列。
- **依赖**：P1。
- **验收**：**空帝国自举测试**——从 1 spawn + 300 能量开始，无任何人工 flag/console，
  30 万 tick 内达到 RCL3+ 且 tower 在建；关键角色死亡自动补位。
- **回退**：紧急车道保证灾后最小产能重建。

### Phase 3 — 产能闭环（→A2 前半）
- **交付**：RCL4 storage 经济切换；能量收支核算（净流、储备、预算）；请求池物流
  完整版（租约/超时回收/空载观测）；tower 能量补给并入物流。
- **依赖**：P2。
- **验收**：能量净流连续 5 万 tick 为正；hauler 空载率 < 阈值；低能量注入场景
  （清空 storage）在限定 tick 内恢复。
- **回退**：container 缓冲兜底（断链 fallback）。

### Phase 4 — 房间发展自动化（→A2 后半）
- **交付**：版本化布局模板 + 约束适配校验；建造优先级与 site 配额；RCL5 link
  网络自动化；交通热度铺路（数据采集→逐段建路）；phase 推进逻辑（锚定能力相变点）。
- **依赖**：P3。
- **验收**：RCL1→RCL6 全程无人工干预且模板冲突只标 blocked；link 网自动维持
  storage 水位；道路只出现在实测热路径上。
- **回退**：模板版本迁移；blocked 结构不阻塞其余建造。

### Phase 5 — 远矿（Remote Mining）（→A3 前半）
- **交付**：远矿车道（Agenda 项：预算/期限/取消条件）；reserver；remote hauler；
  威胁感知下的自动撤退与恢复；ROI 核算（CPU 定价：remote 房 ~1 CPU/房 数据点 +
  效率 40–50% 递减规律）。
- **依赖**：P4（人口与物流稳定才有余量）。
- **验收**：远矿净收益连续为正才保持；敌袭自动暂停并 N tick 后自动恢复；CPU 紧张
  （Recovery 档）时远矿最先被砍。
- **回退**：降级为纯本地经济（社区先例：shard3 玩家完全砍掉 remote 仍存活）。

### Phase 6 — 多房与帝国协调（→A3 中）
- **交付**：房间注册表；帝国态势快照；跨房资源调拨（terminal 均衡 + 运费核算）；
  市场系统（阈值制、getAllOrders 低频缓存、边际价值决策）。
- **依赖**：P5（运输余量与预算门控先存在）。
- **验收**：单房故障（能量清零/失守模拟）不拖垮帝国；调拨遵守「本土净流为正」
  门控；无重复市场订单（幂等键验证）。
- **回退**：调拨降级为房内自给模式。

### Phase 7 — 扩张（→A3 完成）
- **交付**：候选评分（source/矿物/距离/邻接安全）；资源门控（CPU 平滑指标 +
  本土净流 + 运输余量，TooAngel 式指数平滑指标）；殖民自举车道（殖民 creep 落地
  自续命 + 母房 5000 能量输血 + 工地 rampart 保护）；失败撤离路径。
- **依赖**：P6；GCL 是硬上限。
- **验收**：扩张决策可解释（记录评分与门控快照）；殖民失败在期限内自动降级为
  remote 或放弃；帝国 CPU 不因扩张进入 Guarded 以下。
- **回退**：收缩为既有房间运营。

### Phase 8 — 防御体系（→A4 前半）
- **交付**：威胁检测与分级（body/数量/boost/补给评估）；防御 policy 状态机
  （normal→alert→siege→recovery）；tower 目标策略与能量会计（围城耗能是社区确认
  的头号破防手段）；safemode 预算管理（每 shard 一房、spawn<50% 血量类触发惯例、
  nuke 语义）；min-cut rampart 维护。
- **依赖**：P4（结构布局）+ P3（能量核算）。
- **验收**：威胁注入（模拟敌编队）触发正确分级与响应；围城模拟能量不枯竭
  （储备+补给速度达标）；safemode 决策有记录与冷却遵守。
- **回退**：fortify posture 静态防御。

### Phase 9 — 军事（→A4 完成）
- **交付**：war posture 授权链（持续被打+打得起）；war-planner（唯一进攻决策者）；
  小队组织与 boost 前置（quad/duo 社区收敛形态）；止损链（伤亡阈值收摊/黑名单
  冷却/经济压力退 fortify）；战后核验（只信新鲜 intel）。
- **依赖**：P8（防御成熟才有战争经济余量）+ P6（帝国资源调配）。
- **验收**：战争全程经济不越过红线（战争账本）；止损条件触发即收摊；波次集结
  满编才推进。
- **回退**：退 fortify；黑名单冷却防死缠。

### Phase 10 — 高级经济（energy sink 规划）
- **交付**：lab 反应链（按真实 boost 倍率表核算产能）；factory 商品链（按需而非
  解锁即建）；power 采集与 power creep（OPERATE_* 优先级：spawn/lab/tower）；
  RCL8 后能量 sink（GCL farm 房 / temple / power spawn 消化富余——社区确认后期
  能量过剩是常态）。
- **依赖**：P6 市场 + P7 扩张（矿物多样性）。
- **验收**：每条生产链有输入库存/输出消费/降级策略；boost 库存满足军事 SLA。
- **回退**：生产链独立降级不伤基础经济。

### Phase 11 — 自愈强化与 Soak（→A5）
- **交付**：完整自愈闭环（Monitor→Anomaly→Diagnosis→Recovery→Verification，
  见 [22_SELF_HEALING.md](22_SELF_HEALING.md)）；遥测面板（segment 低频导出）；
  故障注入测试矩阵全绿；长期 soak（指标趋势无退化）。
- **依赖**：全部（自愈是元能力）。
- **验收**：A5 门槛——soak 中无 Memory 单调膨胀、无任务饥饿、无 bucket 枯竭、
  global reset 后 MTTR 达标；场景矩阵（见 [28_TESTING_STRATEGY.md](28_TESTING_STRATEGY.md)）全过。
- **回退**：降级到上一门槛状态运行。

### Phase 12 — 跨 shard（可选，仅当目标需要）
InterShardMemory + portal 搬迁；独立验证跨 shard 状态与故障边界。默认不启用。

## 5. MVP 重定义（总任务书 §33 的验收答案）

**MVP = A1 + A2**：把一个完全空白的新帝国（1 spawn、300 能量、空 Memory）交给
AI，无任何人工 flag/console 指令，验证：

1. 自举生存链建立（miner/hauler/upgrader/builder 自动就位）；
2. 达到并稳定运营 RCL4+ storage 经济（能量净流为正）；
3. 关键 creep 死亡自动补位；低能量注入后自恢复；
4. 全程 CPU 有预算与降级记录。

这是「自治能力」的最小可验证集合，不是功能清单。人类只提供启动条件（发布代码）。

## 6. 依赖关系图

```text
P1 基座 ─→ P2 生存闭环 ─→ P3 产能闭环 ─→ P4 房间发展 ─→ P5 远矿 ─→ P6 帝国协调 ─→ P7 扩张
                                              │                              │
                                              └──────→ P8 防御 ──────────────┴─→ P9 军事
P6 ─→ P10 高级经济；P11 自愈/soak 横切所有 Phase（自 P1 起逐步强化）
```

关键非显然依赖（研究结论）：
- **防御（P8）先于军事（P9）**：战争经济依赖防御成熟度（ADR-009）。
- **远矿（P5）先于扩张（P7）**：扩张门控需要远矿的 CPU/收益定价数据。
- **自愈横切**：不是最后一个 Phase 才做，而是每个 Phase 带自己的故障注入验收。

## 7. Alternatives Rejected

- 「Economy→Military 两大块瀑布」：无验收判据、依赖不可见。
- 「先 OS 内核后业务」（Quorum 路线）：前置基础设施投资与维护负担被社区演化
  证伪（ADR-002）。
- 「MVP=能跑起来」：无法验证自治，等于没定义。

## 8. Open Questions

1. P7 扩张评分中「宿敌邻接」权重需要实际 PvP 数据校准（当前只有定性证据）。
2. soak 时长与指标阈值的量化标准（A5）需要首个长期运行数据回填。
3. 跨 shard（P12）是否值得做的裁决推迟到 A5 达成后。
