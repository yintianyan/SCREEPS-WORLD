# LLM_BOUNDARY · 外部智能边界契约

> 本文件是 LLM/外部控制平面（external control plane）在本系统中合法位置的**冻结契约**；
> 结构性修订必须走 [ARCHITECTURE_FREEZE.md](ARCHITECTURE_FREEZE.md) §15 修订记录，
> 不得静默修改。依据：[ARCHITECTURE_RECONCILIATION.md](ARCHITECTURE_RECONCILIATION.md)
> §9、research/23（核心，全部 CONFIRMED）、ADR-011。

## 1. 边界合同

> **硬性律令：LLM/外部控制平面不得进入 tick 执行路径；若引入，必须异步化、可超时、
> 可降级，且外部服务不可用时帝国仍能安全运行。**（与 AGENT.md「LLM 与外部服务边界」
> 条款逐字一致。）

| 依据 | 内容 |
| --- | --- |
| 物理依据 | Screeps 脚本运行在服务器端沙箱，API 面无任何出站网络能力（无 HTTP/fetch/WebSocket，官方 API 全部为游戏对象操作）；外部与 bot 的唯一通道是官方 REST API（读写 Memory/RawMemory segment、推送代码）。**LLM 在物理上不可能进入 tick 执行路径**（research/23 §3.1，CONFIRMED）。 |
| CPU 依据 | tick 内配额按 CPU 计且不可透支；远程推理延迟以秒计、不可预算、不可超时控制——与 tick 运行时的时间结构不兼容。 |
| 架构依据 | 确定性（同输入同输出可回归）、可预算（成本静态可知）、可回滚（建议只落在有界参数层，影响半径受限）——三者是自治契约的根基，任何体内引入即破坏全部三条。 |
| 先例依据 | 截至 2026-08 调研，**无任何已知长期存活的高水平 bot 在线上决策路径使用 LLM 或在线学习**；唯一已知 LLM×Screeps 集成（derek 体外大脑）为纯规划、无运行数据（research/23 §3.2）。 |

### 1.1 「进入 tick 执行路径」的判定（越界即违规）

| # | 形态 | 判定 |
| --- | --- | --- |
| 1 | tick 内直接调用外部推理（同步/异步） | **物理不可达 + 违规** |
| 2 | Memory 轮询指令通道常开：体外写入的「指令」被运行时无条件执行 | **违规**——体外写入内容必须过 schema 校验+幂等+过期+预算上限，非法即拒；且消费点只能是 §2 声明的层（L2=参数白名单） |
| 3 | 体外生成的代码未经质量门槛直接推送上线 | **违规**（§3-3） |
| 4 | 体外低频调参经护栏写入 tuning 覆盖层，运行时按正常参数表读取 | **合法**（唯一体内消费形态） |
| 5 | 体外读遥测/读代码做研究、生成 PR、人工评审后发布 | **合法**（L1/L3） |

## 2. 允许清单（三层，全部体外）

| 层 | 定位 | 输入 | 输出 | 护栏（必须全部满足） | 生效路径 |
| --- | --- | --- | --- | --- | --- |
| **L1 开发期研究员**（当前已实践） | 开发流程内的设计/审计助手 | 代码、文档、issue、研究层结论 | 设计、迁移方案、审计结论 | 本地质量门槛（`npm run typecheck` / `npm test` / `npm run build` 全绿）+ 人工评审 | git 提交与发布流程（体外 CI） |
| **L2 运营期低频参数顾问**（可选演进） | 运营期调参候选来源之一 | RawMemory segment 遥测聚合（低频导出） | **有界参数调整建议**（仅候选值，非指令） | ①**参数白名单**（仅 tuning 覆盖层声明的参数，如 EMA 的 D_d/open_d/close_d/N_d）；②**值域与单调性校验**（越界/非法即拒）；③**统计窗口约束**（调整周期不短于统计窗口，防噪声驱动调参）；④**canary 生效**（建议先作用于可观测子集）；⑤**自动回滚**（观察窗口内指标劣化即回退）；单一建议源，禁止多顾问竞争 | **消费点唯一：tuning 覆盖层**（tuned 类机制）——运行时读到的永远是经护栏过滤的合法参数值，LLM 输出本身永不被运行时直接读取 |
| **L3 灾难接管辅助**（人工在场） | 人工授权下的诊断助手 | 灾难现场数据（segment 遥测/Memory 导出，人工提供） | 诊断与恢复方案建议 | 人工授权在场（对应自治契约保留的两条人工边界：发布与灾难接管）；一切动作仍经发布流程 | 与 L1 相同（发布流程）；**不存在**「LLM 方案 → 线上生效」的直通路径 |

**L2 附加约束**：建议生效延迟受统计窗口下限约束（不短于窗口）；遥测导出走 segment
低频写入（每 N tick 聚合一次），已在遥测管线预算内，不新增 tick 成本（research/23 §9）。

## 3. 禁止清单（五条，绝对红线）

| # | 禁止项 | 内容与依据 |
| --- | --- | --- |
| 1 | **tick 内决策** | 移动/攻击/spawn/建造/交易的下达，一律不得由 LLM 或任何外部控制平面参与——物理不可达 + 架构禁止（§1） |
| 2 | **事实裁决** | 游戏机制数值、API 行为一律以引擎常量与官方 typings 为准；LLM 输出（含幻觉的 boost 倍率、成本数字）不得作为事实源（research/23 §8） |
| 3 | **未验证代码直上生产** | LLM 生成代码必须经本地验证门槛（typecheck/test/build 全绿）+ git 回滚；禁止线上自动改代码 |
| 4 | **schema 绕过** | 不得修改 Memory schema 或绕过迁移器写状态；经体外通道写入的任何指令必须 schema 校验、幂等、带过期与预算上限，非法即拒 |
| 5 | **自部署闭环** | 线上 bot 不得改自己的代码；发布永远走体外 CI——禁止自我复制/自我部署闭环 |

## 4. 分层图（任务书 §22 形态，按研究结论修订标注）

```text
┌─ 帝国运行时（tick 执行路径）────────────────────────────┐
│  Kernel → Systems → RolePolicy/唯一写者 → World          │
│  ※ 确定性、可预算、可回滚；无出站网络 → LLM 物理不可达 ※  │
│  唯一外部数据入口：Memory/RawMemory segment（经 REST     │
│  写入的内容必须过 schema 校验+幂等+过期+预算上限）        │
└──────────────┬─────────────────────▲─────────────────────┘
     读(低频导出)│                     │ 写(护栏过滤后的参数值)
┌──────────────▼─────────────────────┴─────────────────────┐
│  tuning 覆盖层（L2 唯一消费点；建议≠指令，只供候选值）    │
└──────────────▲───────────────────────────────────────────┘
               │ 经护栏（白名单/值域/窗口/canary/回滚）
┌──────────────┴──────────────── 体外（开发/运营机）───────┐
│  L1 开发期研究员：代码/文档 → 设计/迁移/审计（人工评审）  │
│  L2 运营期参数顾问：segment 遥测 → 有界参数建议（可选）   │
│  L3 灾难接管辅助：人工授权 → 诊断/恢复方案（人工在场）    │
│  ※ 三层全部体外；发布一律走体外 CI ※                     │
└──────────────────────────────────────────────────────────┘
```

修订标注：任务书原图若含「LLM 参与线上决策/规划」的任何形态，按 research/23 §11
否决（线上 LLM 决策、Memory 轮询指令通道常开、在线 RL、Multi-Agent 协商全数否决）；
唯一存留形态即上图三层体外结构（research/23 §10.2）。

## 5. 降级合同

| 条款 | 内容 |
| --- | --- |
| 安全运行义务 | **外部服务（LLM/API/任何体外组件）不可用时，帝国必须照常安全运行**——自治契约不依赖体外组件；自治的来源是闭环完整性（五环互相供养），不是外部智能（调和 §8）。 |
| tuning 回退 | tuning 覆盖层无合法外部建议时回退到编译期默认参数表；参数缺失/非法一律按默认值处理并告警，绝不阻塞启动或 tick。 |
| 通道降级 | 遥测导出、segment 写入失败不影响 tick 路径（低频重试）；体外读到的数据陈旧只影响建议质量，不影响帝国行为正确性。 |
| 验收口径 | 本合同的降级语义是 A0 门槛（可运行）的一部分：空/旧 Memory 与外部组件全缺位时，帝国仍满足生存闭环（A1）运行条件。 |

## 5.1 失败模式表（护栏必须覆盖）

| 失败模式 | 后果 | 防线 |
| --- | --- | --- |
| LLM 生成代码直接上线 | 逻辑错误毁掉帝国 | 质量门槛三件套全绿 + git 回滚 + 禁止线上自动改代码（§3-3/5） |
| LLM 幻觉机制事实（错误 boost 倍率等） | 战斗/经济决策系统性错误 | 一切数值以引擎常量与 typings 为准；LLM 输出不得作为事实源（§3-2） |
| Memory 指令通道被无条件信任执行 | 体外故障放大到线上 | schema 校验、幂等、带过期与预算上限，非法即拒（§1.1 形态 2） |
| 建议噪声驱动调参 | 参数震荡传导进 posture/预算 | 统计窗口约束 + canary + 自动回滚（§2 L2 护栏） |
| 把 Manager/组件冠名 Agent 的概念污染 | 架构评审失去判据 | [AGENT_ARCHITECTURE.md](AGENT_ARCHITECTURE.md) 判据与命名禁令 |

## 6. 评审红线（汇总）

1. 任何「让 LLM 参与 tick 决策/规划」的提案——立即否决（§1、§3-1）。
2. L2 建议绕过白名单/值域/canary/回滚任一护栏直达运行时——立即否决（§2）。
3. 运行时代码读取 LLM 原始输出（而非护栏后的参数值）——立即否决（§2 消费点条款）。
4. LLM 输出被用作游戏机制事实源——立即否决（§3-2）。
5. 任何线上自改码/自部署路径——立即否决（§3-5）。
