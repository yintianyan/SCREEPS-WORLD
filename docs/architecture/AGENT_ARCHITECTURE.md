## 1. Agent 判据合同（唯一判据）

> **一个组件是 Agent，当且仅当它在运行时拥有「目标选择权」（goal selection
> authority）——即能改变「帝国现在追求什么」，而不仅仅是「如何执行既定目标」。**
> （research/23 §10.1 判据；调和 §5 将其从研究结论升格为命名规约，全仓库强制。）

| 条款 | 内容 |
| --- | --- |
| 必须 | 任何新组件的架构评审必须先回答：「它拥有运行时目标选择权吗？」——答案唯一决定其能否冠名 Agent。 |
| 禁止 | 以「智能程度」「自治程度」「复杂度」「是否用 LLM」作为 Agent 判据——这些都不是判据；Overmind 的 Overlord/Overseer 名字像 Agent 但实质是确定性控制器（research/05 §4）。 |
| 全系统结论 | 满足判据的组件**恰好一个**：帝国战略层（Policy 纯函数载体）。「Agent」是职责描述，不是运行时设施——**本系统无 Agent Runtime 合同**（无信念系统、无协商总线、无通用自主层）。 |

### 1.1 判据的操作化（评审三问）

任何组件按下表三问过堂，任一问答错即驳回冠名：

| # | 问题 | Agent 答案 | 确定性系统答案 |
| --- | --- | --- | --- |
| Q1 | 它能改变「帝国现在追求什么」吗（posture/预算/立项授权）？ | 能 | 不能——只在既定目标内选择手段 |
| Q2 | 它的决策输入是态势级摘要还是本地/瞬时数据？ | 态势级摘要（快照） | 本地或瞬时数据 |
| Q3 | 同一输入是否必然同一输出（可快照回放单测）？ | 必须是（受限 Agent 仍是纯函数） | 必须是 |

Q1 是判据本体；Q2/Q3 是辅助鉴别——「聪明的启发式」「自适应参数」「学习式评分」再
复杂，只要过不了 Q1，就不是 Agent，也不得因此获得任何特殊架构地位。

## 1.2 架构形态裁决（Model A–E 摘要）

> 任务书 Model A–E 五候选的完整裁决见 research/05 §5；结论：**采纳修订版 Model D**。

| 模型 | 形态 | 裁决 | 一句话理由 |
| --- | --- | --- | --- |
| A 房间自决 | 对等节点、无帝国决策 | **否决** | 跨房资源死锁无仲裁；扩张/战争无授权链（ADR-001 Options A） |
| B 帝国集中命令链 | 帝国→房间→creep 逐层下达 | **否决** | 帝国层带宽与 CPU 不可承受；本地闭环被远端延迟拖垮 |
| C 战略→计划→房间 | 战略层产出计划序列 | **否决**（正确内核被吸收） | 全量计划序列在对抗世界脆断；社区零先例 |
| **D 修订版（裁决）** | Goal→Policy→AgendaItem→Demand→Task→Action→Outcome 语义链（Demand 为瞬时层） | **采纳** | 与 bonzAI Operation–Mission、TI request、Overmind directive-overlord-task 存活先例同构；修订点：Plan 降格为 Agenda 里程碑、Goal 去竞拍化、补 Demand 层 |
| E 分层 Agent 社会 | 多 Agent 协商网 | **否决** | 见 §4 六点否决 | |

## 2. 组件盘点表（谁是 Agent，谁是确定性系统）

> 唯一受限 Agent 的三重约束：**纯函数 + 滞回 + 遥测**（research/05 §10.2）——自治性
> 被压缩进一个可单测、可快照、可回放的黑盒边界内。

| 组件 | 判定 | 理由 |
| --- | --- | --- |
| **帝国战略层**（posture×budget 决策器，Policy 纯函数载体） | **受限 Agent（全系统唯一）** | 唯一拥有目标选择权（peace/fortify/war、扩张/收缩、预算分配）；本身是确定性纯函数，同输入同输出 |
| Kernel（调度/隔离/预算/迁移四职能） | 确定性系统 | 维护运行秩序，不感知目标（见 KERNEL_ARCHITECTURE） |
| Agenda 管理器（AgendaItem 生命周期） | 确定性系统 | 只执行创建/复核/取消规则；目标已由战略层选定 |
| 各 System（spawn/物流/建造/远矿/防御/战争执行/市场/intel/交通/房间系统） | 确定性系统 | 全部是「如何执行既定目标」；唯一写者们管理独占写权（SpawnManager/ConstructionManager/RemoteMiningManager/MarketManager——Manager 仅保留给唯一写者资源代理，调和 §5） |
| RolePolicy / creep | 确定性执行器 | 声明式策略驱动的 FSM；无目标选择、无 spawn 请求权、无全房扫描权 |
| 分配服务（评分认领/租约绑定） | 确定性系统 | 查表+排序；合同网的去协商化形态 |
| 自愈监视 | 确定性系统 | 签名→处置表查表，不做猜测性修复（research/22） |
| 演化闭环（有界参数调节） | 确定性系统带护栏 | 参数调整走统计窗口+canary+自动回滚；红队元结论：自适应自身是振荡源，故每次调整带承诺期与预期状态核对（research/30 §4） |
| 遥测/观测管线 | 确定性系统 | 采样、聚合、告警均为规则 |
| 体外 LLM 顾问（若引入 L2） | **工具，非 Agent** | 无运行时目标选择权；建议采纳权在护栏/canary 流程（见 [LLM_BOUNDARY.md](LLM_BOUNDARY.md)） |

## 3. 「Agent」命名禁令

| 条款 | 内容 |
| --- | --- |
| 后缀禁令 | **任何新组件禁止使用 Agent 后缀**（XXXAgent 非法）——Agent 判据全系统仅一处满足，冠名权已由战略层占用；违规命名在评审即驳回（research/05 §10.3 实施纪律）。 |
| 配套术语规约 | 与调和 §5 一致：**System**＝组合根注册的 tick 管线成员；**Service**＝无状态纯逻辑集合（domain 层）；**Manager** 仅保留给唯一写者资源代理；**engine**＝执行框架（role-runner/traffic resolver）。禁止 Coordinator/Handler/Controller 等空转命名；一个模块若只是转发/调用/if-else 必须删除。 |
| 非运行时设施 | 禁止以「Agent 需要」为由引入任何运行时设施（信念库、意图栈、协商总线、Agent 框架）；BDI/GOAP/Utility 竞拍/在线 RL 的否决依据见 research/05 §11 与 research/23 §11。 |
| 层级穿透禁令 | Goal/Policy 类型不得出现在执行层 import 面；角色层读/改 posture 即架构 bug（research/05 §8）。 |

## 4. Multi-Agent 社会否决摘要（六点）

> 对象：Model E 及一切变体（房间 Agent 协商、creep Agent 自组织、帝国-Agent 谈判）。
> 完整论证见 research/05 §11。

| # | 否决点 | 内容 |
| --- | --- | --- |
| 1 | 无先例 | 全部调研对象（7 家，源码级核查）零家采用多 Agent 协商；十年级存活样本全部是确定性分层 |
| 2 | CPU 结构性爆炸 | 协商语义每 tick 每节点都要消息处理；30 房规模仅消息路由即超多数系统全部预算——结构性否决，非实现优化问题 |
| 3 | 不确定性爆炸 | 协商结果依赖消息时序与轮次，同一态势产出不同决策——摧毁「可单测、可回放、可审计」根基，而可审计性是自治契约前提 |
| 4 | 解决的问题不存在 | 协商解决「多个自主主体的目标冲突」；本架构通过 posture 允许集 ∩ 预算门控 ∩ 优先级序在**决策之前**消解目标冲突，不需要事后谈判 |
| 5 | 涌现行为不可审计 | 自治契约要求每个行为可追溯到决策快照；多 Agent 涌现行为天然不可追溯，故障归因成本超线性增长 |
| 6 | 合理内核已保留 | 合同网的「招标-认领-租约」**语义**（不协商、只认领）保留在请求池物流与 TI 式请求经纪中 |

## 5. 自治诚实分级要求（报告义务）

> 先例：bonzAI 的 README 把「从结果与随机变异演化」的愿景与「当时选房仍需人工」的
> 现状**分开陈述**——被社区视为诚实做法；夸大自治度损害可信度（research/23 §3.2/§4）。
> 本项目采用同一纪律。

| 条款 | 内容 |
| --- | --- |
| 双列陈述义务 | 任何对外/对内描述自治能力时，**愿景（target）与当前覆盖率（actual）必须分开陈述**；「完全自治」只能作为目标态表述，不得作为现状表述。 |
| 门槛锚定义务 | 现状陈述必须锚定验收门槛（research/27 §3）：A0 可运行 / A1 生存闭环 / A2 产能闭环 / A3 多房自治 / A4 威胁下运营 / A5 长期不退化。例：「当前 A2：单房能量净流稳定；远矿与战争自治未实现」。 |
| 人工边界声明 | 未达 A5 前，现状陈述必须显式列出残余人工介入点（发布、灾难接管两条边界之外的一切介入）；自治升级的每次宣称必须附遥测证据（哪个指标驱动、什么护栏）。 |
| 评审纪律 | 评审时对「智能」「学习」「自适应」词汇要求证据（哪个指标驱动、什么护栏，research/05 §10.3）——与 AGENTS.md 自治契约的零人工干预常态表述一致：宣称与证据同行。 |
| 报告模板 | 现状报告必须含三行：① 当前门槛（A0–A5 及证据链接）；② 已自治域清单（按 A 门槛映射）；③ 残余人工介入点清单。禁止只写愿景不写覆盖率，禁止把「设计已含」表述为「已运行」。 |
| 升级义务 | 门槛跨越（如 A2→A3）的宣称必须附 soak 遥测证据；A5 之前任何「完全自治」的现状化表述均视为违规（红队 A10 的教训同样适用：合理停滞与真实退化必须区分陈述）。 |
