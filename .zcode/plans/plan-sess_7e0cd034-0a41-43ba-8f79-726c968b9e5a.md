## 2. 常量唯一真相源（核心设计决策）

**事实依据（已验证）**：`@screeps/driver`（已在依赖树：`screeps` 的依赖 + mockup 的 peerDep ^5.1.0）导出 `constants` 共 **423 个官方键**，覆盖全部所需：`FIND_*`、`CONTROLLER_LEVELS`（=RCL progress 表）、`CONSTRUCTION_COST`、`BODYPART_COST`、`REPAIR/BUILD/HARVEST/UPGRADE_POWER`、`SAFE_MODE_*`、`CONTROLLER_DOWNGRADE`、`CONTROLLER_STRUCTURES`（setup.ts:142 手写表可整表删除）。

**关键发现**：现行 `tests/setup.ts:69-79` 的 `FIND_SOURCES=1/FIND_MY_STRUCTURES=6` 等是**测试私有编码**（真实官方值 FIND_SOURCES=105、FIND_STRUCTURES=107），TestWorld 的 `find()` switch 与之配套自洽。这不是"官方常量副本"而是"假编码"——它使 integration 层永远无法用官方值做断言，且 `BUILD_COST.spawn=30000` vs 官方 `CONSTRUCTION_COST.spawn=15000` 已是实际漂移。

**方案**：
1. `@screeps/driver` 加为显式 devDependency（锁定当前树内解析版本）。
2. `support/constants.ts` = `export const C = require("@screeps/driver").constants` 全量 re-export + 极少量补充（仅 driver 缺失项，逐条注释官方出处）。
3. setup.ts 注入官方值（fake 编码退役）；TestWorld `find()` switch 同步换官方编码（`FIND_EXIT` 单常量官方不存在 → 用 `FIND_EXIT_TOP/RIGHT/BOTTOM/LEFT` 四常量分支）。
4. **防漂移哨兵**：新增 `tests/e2e/scenarios/27-constants-parity.test.ts`——boot 一次真实 server，sendConsole 输出运行时全局常量子集（FIND_/STRUCTURE_/ERR_ 等玩家可见项），与 `support/constants` 逐键比对。runtime 不可见的表（CONTROLLER_LEVELS 等）由 driver 版本锁 + mockup 版本锁间接覆盖。
5. 已核实迁移风险≈0：`src/` 与 `tests/` 中 `find(<数字>)` 直呼字面量为 **0 处**；测试内本地 `FIND_*=数字` 定义仅 **10 处**，随本期一并删除改 import。
